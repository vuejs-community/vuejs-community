# Adding a Project Data Entry

## Scope

This skill only applies when creating data files under `src/` of the following 7 packages. Do not use it anywhere else:

| Data package | Fixed `category` value |
| --- | --- |
| `packages/data-ui/src` | `'ui'` |
| `packages/data-component/src` | `'component'` |
| `packages/data-hooks/src` | `'hooks'` |
| `packages/data-nuxt/src` | `'nuxt'` |
| `packages/data-plugins/src` | `'plugin'` |
| `packages/data-uniapp/src` | `'uniapp'` |
| `packages/data-admin/src` | `'admin'` |

## Core Rules

1. Follow the `defineProjectMeta` function in the `@vuejs-community/schema` package and export entries as `export default defineProjectMeta({...})`.
2. The argument passed to `defineProjectMeta` must strictly conform to the `CommunityProject` type definition (`packages/schema/src/types.ts`). Do not add any fields beyond that type.
3. The file name must match `name` (kebab-case). For `data-plugins`, files must go into the `src/vite|rollup|rolldown|unplugin/` subdirectory matching the plugin type; in all other packages (including `data-uniapp`), files go directly under `src/`.
4. Note: files under `data-nuxt/src` are auto-generated by `pnpm run generate:nuxt:modules` from the official nuxt/modules list. Never manually modify existing files; only manually create modules that are missing from the official list.
5. `data-uniapp` collects uni-app ecosystem projects (component libraries, templates, plugins, tools, etc.; `types` such as `component-library`, `mobile-ui`, `template`). `data-admin` collects admin systems and admin dashboard templates (`types` such as `admin-template`, `fullstack-template`, `template`). Always pick `types` from `ProjectType` based on the project's actual form.

## File Template

The Chinese text in the template are field descriptions; replace them with real values when creating a file. Optional fields without data (`tags`, `filter`, `website`, etc.) may be omitted, but `stats` must be written in full (except for `data-admin`, see the next section).

```ts
import { defineProjectMeta } from '@vuejs-community/schema'

export default defineProjectMeta({
  name: 'Project name',
  description: 'Project description',
  category: 'The data category this project belongs to; see the ProjectCategory type definition',

  types: ['Types the project can be assigned; see the ProjectType type definition'],

  tags: ['Tags assigned to the project'],

  filter: ['Keywords used to filter the project, if filtering is needed'],

  links: {
    github: 'Full GitHub URL of the project',
    npm: 'Full npmjs URL of the project',
    website: 'Official website URL of the project',
  },

  source: {
    github: 'GitHub repo slug of the package, in the format: owner/repo',
    npm: 'Package name on npmjs',
  },

  stats: {
    stars: GitHub star count of the project,
    downloads: {
      monthly: Monthly download count on npmjs,
      weekly: Weekly download count on npmjs,
    },
  },
})
```

## stats Requirements

When creating files with this skill: if the project has no npm package, its corresponding `stats.downloads` defaults to `0`. If the project has a git repo, the star count must be stated explicitly — never omit it, never fill in `0`, never fabricate it. Fetch it live from the following endpoints at creation time:

- `stars`: request `https://api.github.com/repos/{owner}/{repo}` and take `stargazers_count` from the response; if the API is rate-limited or unreachable, fall back to `https://ungh.cc/repos/{owner}/{repo}` and take `repo.stars` from the response.
- `downloads.monthly`: request `https://api.npmjs.org/downloads/point/last-month/{package-name}` and take `downloads` from the response.
- `downloads.weekly`: request `https://api.npmjs.org/downloads/point/last-week/{package-name}` and take `downloads` from the response.

Exception: admin templates/systems collected in `data-admin` are not published to npm and have no download data — their `stats` contains only `stars` (still fetched live from the GitHub API), with the entire `downloads` field omitted rather than filled with `0`:

```ts
stats: {
  stars: GitHub star count of the project,
}
```

## Post-creation Validation

After creating the file, run `pnpm eslint --fix <file-path>` to fix and validate the formatting.
